# Почему уходят

Рабочий прототип для тестового «НОВИЧОК». Пользователь — HR-партнёр компании спорттоваров: около 400 сотрудников, розница, склад, продажи и офис.

**Гипотеза:** причины ранних уходов остаются внутри административных задач на увольнение. Если собрать их в единую структуру и привязать повторяющийся сигнал к действию, HR сможет выбирать конкретные улучшения найма и адаптации. Гипотеза не подтверждена интервью с компанией.

## Запуск

Нужен Node.js 20+. Устанавливать пакеты не требуется.

```sh
npm run dev
```

Открыть http://127.0.0.1:4173. Для другого порта: `PORT=8080 npm run dev`.

```sh
npm test
npm run check
npm run build
```

`dist/` — готовый статический сайт. Можно разместить на любом статическом хостинге. Используются относительные пути: подкаталог тоже поддерживается. Node нужен только для локального сервера, сборки и тестов; браузерный интерфейс написан на HTML/CSS/JS без зависимостей. Manrope подключается через Google Fonts, при отсутствии сети используется системный шрифт.

## Сценарий демонстрации (2–3 минуты)

1. В обзоре увидеть 18 ранних уходов из 54, три повторяющихся сигнала.
2. Открыть «Разобрать» в карточке «График / Магазин Центр». Посмотреть пять исходных записей и источники ответов.
3. Создать действие: ввести ответственного, проверить срок и способ проверки результата. Оно появится в «Действиях».
4. Нажать «Изменить», перевести задачу в «В работе» или «Выполнено». Перезагрузить страницу — изменение сохраняется.
5. Добавить увольнение с датой приёма 01.10.2026 и датой ухода 11.11.2026. Вернуться в обзор: показатели и сигнал пересчитаны.
6. Проверить фильтр подразделения, переключатель стажа и выгрузку CSV. В «О данных и методике» доступны JSON-копия, восстановление и сброс демо с подтверждением.

## Данные и расчёты

- Все коды, события и комментарии вымышлены. Сценарная дата фиксирована: **11.11.2026**.
- Исходно 54 увольнения в 2026 году, 18 со стажем менее 90 календарных дней; пример соответствует «каждый третий из ушедших». Это **не означает**, что треть всех нанятых уходит до 90 дней.
- Дни стажа считаются по датам UTC, граница 90 исключается. В задании сказано «три месяца»; для MVP принято явное приближение 90 дней.
- Первый показатель: ранние / все увольнения, с учётом периода, подразделения и причины. Переключатель «до 90 дней» меняет остальные выборки, но не убирает из знаменателя поздние уходы первого показателя.
- Причины на диаграмме относятся только к ранним уходам. «Не указана» остаётся видимой. Полнота причин считается по текущей выборке.
- Сигнал: минимум 3 ранних ухода с одной основной причиной в одном подразделении. Карточка показывает число случаев относительно всех ранних уходов в подразделении текущей выборки и исходные записи.
- Источники: сотрудник, HR, руководитель. Инициатор увольнения хранится отдельно. Причина — версия источника, а не доказательство причинности.
- Одна открытая задача на сигнал: повторная кнопка ведёт в существующие действия. После выполнения можно создать следующую задачу.

## Ограничения

Данные сохраняются в `localStorage` этого браузера, общих данных между пользователями нет. При недоступном или переполненном хранилище интерфейс предупреждает об этом. JSON-импорт проверяет схему, даты, уникальность кодов и идентификаторов; перед заменой предлагает скачать текущую копию. CSV экранирует поля и нейтрализует формулы.

Нет серверной БД, авторизации, анонимного интервью, реальной интеграции с Битрикс24, автоматических уведомлений и доказанного влияния на текучесть. Нужны все наймы и зрелые когорты, чтобы оценивать удержание; сравнение числа уходов по подразделениям без числа нанятых не даёт честного рейтинга. Порог 3 — демонстрационное правило, не статистическая значимость.

Следующий шаг: интервью с HR, проверка полей задач Битрикс24, согласование доступа к ответам, затем чтение приёмов/увольнений и создание задач через серверную интеграцию. До этого прототип предназначен только для вымышленных данных.

## Структура

- `web/domain.js` — расчёты, валидация, CSV.
- `web/data.js` — воспроизводимый набор демоданных.
- `web/app.js` — экраны, формы, хранение и действия.
- `web/styles.css` — адаптивный интерфейс.
- `test/domain.test.js` — тесты бизнес-логики.
- `REPORT.md` — отчёт для сдачи (до 15 строк).
- `QA.md` — фактически выполненные проверки и пределы проверки.
- `.github/workflows/check.yml` — проверки при push и PR.
